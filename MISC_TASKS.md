The `NullPlayer` target finds the vendored framework through `.unsafeFlags(["-F", "Frameworks"])` in its own `swiftSettings` (`Package.swift` ~L166). `NullPlayerAppTests` has no such setting. **Unverified hypothesis:** `@testable import NullPlayer` makes swiftbuild's explicit-module scan of the test target resolve `NullPlayer`'s `import VLCKit`, and unsafe flags don't carry over to dependent targets, so the test target has no `-F Frameworks`. Candidate fixes, in order: give the test target the same `-F Frameworks` swift setting; or make the two imports `internal import VLCKit` so VLCKit isn't exposed through the module's interface. Check the second against the vendored framework's module map. **Done when** a plain `swift test` builds and passes on 6.4, `--build-system native` still passes, and the release DMG still links and plays a video. Then drop the "pass the flag yourself for tests" wording from the two docs above, and keep the products-path note: `scripts/lib/swiftpm.sh` pins native for its own reasons. Skill: `testing`. |

| M13 | A playlist video's end halts the queue in every family but `.wmz` | At the end of a film from the playlist, `VideoPlayerWindowController.markReachedEndOfMedia` → `WindowManager.videoPlaybackDidReachEndOfMedia` calls `audioEngine.stop()` (the engine is `.paused`, since `playVideoTrack` pauses it when the film starts). Then `videoTrackDidFinish` → `audioEngine.next()` sees `.stopped`, so it loads the next row and never plays it. `.wmz` takes `wmpVideoTrackDidFinish` → `advanceAfterNaturalTrackEnd` and continues. Reproduced 2026-10-07 on the debug build (Modern, playlist `audio-short.m4a`, `video-short.mp4`, `audio-short.m4a`): log `WindowManager: Video track finished, advancing playlist` → `loadLocalTrack: audio-short.m4a` → no play. **Decide first:** whether the non-WMP path should also follow natural-end rules (`next()` wraps at the end of the playlist, a natural end stops there). Classic and Original change too, so the fix is an all-modes change by request, not a side effect. Skill: `video-playback`. |

| M15 | Movies and TV rows lack the standard play verbs (**Play Next**, **Add to Queue**, …) | Music rows in both library browsers build their play items from `TrackVerb.addMenuItems` (`App/TrackVerb.swift`: Play, Play and Replace Queue, Play Next, Add to Queue), and Enter / Shift+Enter / Option+Enter run the same verbs. | M16 | `stopLocalForCasting` repeats `haltAudioOutput` by hand, with a stronger stop | `AudioEngine.haltAudioOutput()` is the shared teardown for `stopLocalOnly` and `loadTrack`'s video branch: bump `playbackGeneration`, stop the active pipeline's primary player, `resetLocalCrossfadeStateForDirectPlayback()`. `stopLocalForCasting` (~L2751) runs the same steps by hand, with two differences: it stops **both** primaries (`streamingPlayer` and `playerNode`), and it sets `isLoadingNewStreamingTrack` for 0.1 s around the stop. Its comment says the flag is needed because `AudioStreaming` reports end of stream on an intentional stop, and on radio that runs `RadioManager.streamDidDisconnect` → reconnect, which would restart local radio while Sonos plays the stream. **That premise looks stale:** the vendored `AudioPlayer.stop()` writes `stopReason = .userAction` synchronously, the finish callback reads `stopReason` on main afterwards, and `StreamingAudioPlayer.audioPlayerDidFinishPlaying` forwards only `.eof` / `.none`. So an explicit stop should never reach `streamingPlayerDidFinishPlaying`. The flag does still mask the `.stopped` state callback (`streamingPlayerDidChangeState`), which `haltAudioOutput` does not. Confirm with a log before relying on either. **Decide first:** fold the cast path in with a parameter (`haltAudioOutput(allPipelines:)`), or give every caller the stronger stop. The second option changes Stop and video routing, including the 0.1 s window. **Check at the same time:** the async `.stopped` state from `haltAudioOutput`'s streaming stop lands after `loadTrack`'s video branch returns and sets the engine to `.stopped` while the film plays, which may feed **M13** (`next()` sees `.stopped`). Needs live testing with casting (Sonos + radio). Skills: `audio-system`, `sonos-casting`. |
