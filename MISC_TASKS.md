| M16 | `stopLocalForCasting` repeats `haltAudioOutput` by hand, with a stronger stop | `AudioEngine.haltAudioOutput()` is the shared teardown for `stopLocalOnly` and `loadTrack`'s video branch: bump `playbackGeneration`, stop the active pipeline's primary player, `resetLocalCrossfadeStateForDirectPlayback()`. `stopLocalForCasting` (~L2751) runs the same steps by hand, with two differences: it stops **both** primaries (`streamingPlayer` and `playerNode`), and it sets `isLoadingNewStreamingTrack` for 0.1 s around the stop. Its comment says the flag is needed because `AudioStreaming` reports end of stream on an intentional stop, and on radio that runs `RadioManager.streamDidDisconnect` → reconnect, which would restart local radio while Sonos plays the stream. **That premise looks stale:** the vendored `AudioPlayer.stop()` writes `stopReason = .userAction` synchronously, the finish callback reads `stopReason` on main afterwards, and `StreamingAudioPlayer.audioPlayerDidFinishPlaying` forwards only `.eof` / `.none`. So an explicit stop should never reach `streamingPlayerDidFinishPlaying`. The flag does still mask the `.stopped` state callback (`streamingPlayerDidChangeState`), which `haltAudioOutput` does not. Confirm with a log before relying on either. **Decide first:** fold the cast path in with a parameter (`haltAudioOutput(allPipelines:)`), or give every caller the stronger stop. The second option changes Stop and video routing, including the 0.1 s window. **Check at the same time:** the async `.stopped` state from `haltAudioOutput`'s streaming stop lands after `loadTrack`'s video branch returns and sets the engine to `.stopped` while the film plays. Needs live testing with casting (Sonos + radio). Skills: `audio-system`, `sonos-casting`. |
| M17 | `VideoPlayerWindowController` repeats the server-reporter dispatch about 15 times | The file is 1,911 lines. What is loaded is held in eight optionals (`currentPlexMovie`, `currentPlexEpisode`, `currentPlexRatingKey`, `currentJellyfinMovie`, `currentJellyfinEpisode`, `currentEmbyMovie`, `currentEmbyEpisode`, `currentLocalURL`), read back through `isPlexContent` / `isJellyfinContent` / `isEmbyContent`. Every report goes through the same `if isPlexContent … else if isJellyfinContent … else if isEmbyContent` chain to `PlexVideoPlaybackReporter` / `JellyfinVideoPlaybackReporter` / `EmbyVideoPlaybackReporter`: the four `videoPlayerView` callbacks (pause, resume, position, finished, ~L387–433) and the stop-the-previous-item block at the top of all ten `play(…)` methods (`url`, `plexTrack`, `movie`, `episode`, `jellyfinMovie`, `jellyfinEpisode`, `embyMovie`, `embyEpisode`, `jellyfinTrack`, `embyTrack`, ~L642–1150). `reportCurrentServerVideoStop` (~L500) already does the stop dispatch, but only the two cast paths call it. Each `play(…)` also clears every optional by hand before setting its own. **Direction:** one `enum LoadedVideo` (`.local(URL?)`, `.plexMovie`, `.plexEpisode`, `.plexRatingKey`, `.jellyfinMovie`, …) in place of the eight optionals, set in one assignment, so a new item cannot inherit a stale field. A `reporter` derived from it, behind a small protocol the three reporters already fit (`videoDidPause`, `videoDidResume`, `updatePosition`, `videoDidStop`), so each callback becomes one line. One shared prologue for the `play(…)` methods: reset cast state, report the previous item stopped, record analytics, set `LoadedVideo`. The public `plexMovie` / `jellyfinEpisode` / … accessors read from the enum. Pure refactor: no report, scrobble or log line may change. Check with a Plex film (pause, resume, seek, stop, play another) and compare the reporter log lines before and after. Skills: `video-playback` (*Server progress reporting*). |
| M18 | The video keys do nothing to a film playing inside a `.wmz` skin | Space (play/pause), Left/Right (skip 10 s), F (fullscreen) and Esc never reach a film parked in a `.wmz` skin's video box. They are handled by `VideoPlayerWindowController.setupKeyboardMonitor`, which acts only when its own window is key, main, or fullscreen. While the film is parked, that window is a child of the skin window and never becomes key. Measured 2026-10-07 on the debug build (Cablemusic, Plex `Airplane!`, Library Browser key): Space, Left, Right and F logged nothing and changed nothing. Since the M5 fix, the skin window takes key focus when a film starts, so these keys now go to the skin, which ignores them too. **Do not fix this by making the parked video window key:** Esc there runs `dismissVideoOutput`, which under `.wmz` falls through to `close()` and stops the film (`hideWinampModernVideoSurface` answers only for `.wal`). **Direction:** let the monitor also act while the window the film is parked in is key, and give Esc a `.wmz` meaning first (leave fullscreen only, or hide the skin's video view). Check `.wal` too: its video window is key after a play (`setAuxiliaryWindow`), so it probably has the same gap. Skills: `video-playback`, `wmp-skin-guide`. |
| M19 | Library Browser column header shows one row type's columns over a list of mixed row types | In the Artists tab the right-click column menu lists all three groups (`LibraryColumnVisibility.menuGroups`: Artist 4, Album 5, Track 18 columns), but the header shows one group at a time: `currentVisibleColumns()` picks tracks if any track row is in the list, else albums, else artists. An unexpanded Artists list therefore only ever shows Title, Rating, Albums and Genre, and side scroll stops at Genre, though the menu offers far more: columns ticked under Album or Track columns in that menu never appear on the Artists list, so a ticked column reads as broken. Once an artist is expanded, the header switches to the album columns while every row still draws its own group's columns (`columnsForItem`), so the artist row's album count lands under the wrong heading. Reproduced 2026-10-07 on `211786-Cpro_Winamp_Modern` (embedded classic browser, Plex Artists, double-click Acid King); the Original browser (`ModernLibraryBrowserView`) has the same selection logic. **Decide first:** (1) the header always matches the tab's own rows (artist columns in Artists, album columns in Albums), expanded children show only a title, and the menu lists only that tab's group; or (2) expanded rows keep their own columns under an inline header for each group; or (3) other columns on parent rows. **Done when** every column ticked in the menu for the tab you are on shows on screen (or the menu no longer offers it there). Both browsers. Skill: `ui-guide` (*Library browser list layout*). |
| M20 | Adding a sub-window takes about 40 parallel edits across `WindowManager` and `AppStateManager` | Each centre-stack window (Spectrum, Audio Analysis, PeppyMeter, Art, Flow, Cava, Sonos, Waveform, …) is spelled out by hand in every list that tracks windows. Adding Art (M10) touched about 20 places in `WindowManager`: `CompactWindowSnapshot` field, capture, restore and visibility `switch`; `UIWindowSnapshot` field, capture and restore; the detached-frames struct, capture, restore, apply list and `convScaled`; `managedWindowRecords`, `hostedBorderWindows`, the skin-change fan-out, the mode-dependent and all-windows lists, the close-all teardown, `CenterStackWindowKind` and both kind lookups, `window(for:)`/toggle dispatch, and the post-reflow frame repair. It also touched about 20 in `AppStateManager`: two `AppState` fields, both `CodingKeys` lines, two decodes, two init parameters and assignments, save, the restored-frames table, the show call, and the repair struct's field, parameter, candidate, live window, capture and apply. Missing one place compiles cleanly and quietly drops that window from Compact Mode, a UI switch, UI Size or saved state. M10 collapsed two of these lists (Snap To Default's `centerStackWindowsBelowMain`, the UI-size reflow's `restackSpectrumFamilyWindow`). **Direction:** one table of the centre-stack windows keyed by `CenterStackWindowKind` (window accessor, show, toggle, controller, state key), and snapshots and frame repairs as `[CenterStackWindowKind: WindowSnapshot]` / `[…: NSRect]` instead of a stored property per window. `AppState` keeps its flat `isXVisible` / `xWindowFrame` keys on disk for compatibility, so a custom `Codable` maps the dictionary onto them. **Done when** a new stack window joins every snapshot, restore and repair path by adding one table row, and a test fails if a `CenterStackWindowKind` is missing from it. Pure refactor: no frame, visibility or saved key may change. Check that saved state written before the change still restores (Compact Mode, UI switch, UI Size, relaunch). Skills: `app-state`, `ui-guide`. |
| M21 | Playlist rows mark a video with a `[V] ` text prefix instead of the YouTube rows' video / music glyphs | The Library Browser's YouTube rows mark each form on disk with a text glyph that takes the row's text color: `♫` for audio, `▶\u{FE0E}` for video (`YouTubeMediaKind.rowMarker`, `YouTube/YouTubeRows.swift` ~L102). The playlist spells the same fact as `"[V] "`, built four times by hand: `Windows/Playlist/PlaylistView.swift` ~L339 and ~L780 (Classic), `Windows/ModernPlaylist/ModernPlaylistView.swift` ~L233 and ~L497 (Original/Metal). **Direction:** one marker per `Track.MediaType`, shared by the YouTube rows and the playlist (move `rowMarker` off the `private` extension to a home both can reach), and the four playlist sites read it instead of `"[V] "`. **Decide first:** does every audio row get `♫`, only rows whose origin also has a video (`isYouTubeOrigin`), or none (video keeps its glyph alone)? Marking every audio row puts a glyph on almost the whole list. Check that both glyphs draw in a Classic skin's bitmap playlist font (a skin font with no `♫` / `▶` drops or substitutes it) and at both UI sizes. `.wal` and `.wmz` playlists show no video marker today; say whether they join. Skills: `ui-guide`, `youtube-source`. |
| M22 | A playlist video can start twice on one action | **Play and Replace Queue** on a Plex movie, and double-clicking a video row in the playlist, both log `Video track started` / `Playing video track from playlist` twice. Plex gets a `Video stopped at 0.0s` between the two starts. Measured 2026-10-07 on the debug build (Classic aquamp, Plex `Airplane!` via the browser menu; Original NeonWave, double-click of `Airplane II` in the playlist). **Cause (read, not instrumented):** `loadTracks` (~L4080) and the playlist's play path (~L6615, ~L6675) call `loadTrack(at:)` and then `play()`. `loadTrack`'s video branch (~L4568) sets `currentTrack` and sends `WindowManager.playVideoTrack` through `DispatchQueue.main.async`, so when `play()` runs, `isVideoActivePlayback` is still false. The track's URL is http and no streaming player exists, so `shouldReloadPlaybackPipelineForCurrentTrack` asks for a reload (~L2435) and `loadTrack` routes the film a second time. **Play**, **Play Next** and **Add to Queue** (`playNow` / append) start it once. Local files may skip the reload; check `2-video` too. **Direction:** fix it at the one seam, not in each caller. Either `play()` treats a `.video` `playbackRoute` as owned by the video player, or the video route does not go through `play()` after `loadTrack`. Find out why the dispatch is async (`git log -L`) before making it synchronous. **Done when** each path logs one start, for Plex and for local video. Skills: `video-playback`, `audio-system`. |
| M23 | A queued server video plays with less than the same film started from its row | Double-click on a movie or episode row calls `play(movie:)` / `play(episode:)` / `play(jellyfinMovie:)` …. A video that reaches the window through the playlist (`playVideoTrack`) instead calls `play(plexTrack:)` / `play(jellyfinTrack:)` / `play(embyTrack:)` (`VideoPlayerWindowController` ~L688, ~L1074, ~L1124), which is the path every library-menu verb now takes (M15). Check whether a queued Jellyfin or Emby film reports progress or scrobbles at all. **Direction:** carry enough on the `Track` (rating key / item id plus content type) for the track path to run the same start as the row path, or resolve the server item from its id at play time, so one path serves both. Check against M17, which reshapes the same `play(…)` methods. Check with a Plex episode that has an external `.srt`, queued and double-clicked, and compare the reporter lines. Skills: `video-playback`, `plex-integration`, `jellyfin-integration`, `emby-integration`. |
