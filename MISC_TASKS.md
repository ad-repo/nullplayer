| M18 | The video keys do nothing to a film playing inside a `.wmz` skin | Space (play/pause), Left/Right (skip 10 s), F (fullscreen) and Esc never reach a film parked in a `.wmz` skin's video box. They are handled by `VideoPlayerWindowController.setupKeyboardMonitor`, which acts only when its own window is key, main, or fullscreen. While the film is parked, that window is a child of the skin window and never becomes key. Measured 2026-10-07 on the debug build (Cablemusic, Plex `Airplane!`, Library Browser key): Space, Left, Right and F logged nothing and changed nothing. Since the M5 fix, the skin window takes key focus when a film starts, so these keys now go to the skin, which ignores them too. **Do not fix this by making the parked video window key:** Esc there runs `dismissVideoOutput`, which under `.wmz` falls through to `close()` and stops the film (`hideWinampModernVideoSurface` answers only for `.wal`). **Direction:** let the monitor also act while the window the film is parked in is key, and give Esc a `.wmz` meaning first (leave fullscreen only, or hide the skin's video view). Check `.wal` too: its video window is key after a play (`setAuxiliaryWindow`), so it probably has the same gap. Skills: `video-playback`, `wmp-skin-guide`. |
| M19 | Library Browser column header shows one row type's columns over a list of mixed row types | In the Artists tab the right-click column menu lists all three groups (`LibraryColumnVisibility.menuGroups`: Artist 4, Album 5, Track 18 columns), but the header shows one group at a time: `currentVisibleColumns()` picks tracks if any track row is in the list, else albums, else artists. An unexpanded Artists list therefore only ever shows Title, Rating, Albums and Genre, and side scroll stops at Genre, though the menu offers far more: columns ticked under Album or Track columns in that menu never appear on the Artists list, so a ticked column reads as broken. Both browsers. Skill: `ui-guide` (*Library browser list layout*). |

| M25 | A film that fails to open leaves a black window and a paused engine, with no message | Measured 2026-10-08 on the debug build (Classic aquamp; local library film `short-film`, whose file is gone, played from the playlist after Radio Paradise, and again after a local song): the film window opens and stays black at 0:00, the main window shows pause, and the engine stays `paused` (checked 11 s later). The log has `VideoPlayerView: Playing short-film …` then `VideoPlayerView: Stopped` twice and nothing else: no error, no advance, no close. **Cause (read, not instrumented):** `VideoPlayerView.mediaPlayerStateChanged` handles `.stopped` and `.error` identically (`isActivelyPlaying = false`, `onPlaybackStateChanged?(false)`); neither reports a failure, and only `.paused` at end of media drives `reportPlaybackFinished`. A start that never plays is indistinguishable from a user stop. The engine was paused by `videoPlaybackDidStart`, which runs when the film is handed over, not when it starts playing. A film that played to its end and advanced into the broken one left the engine `stopped` and the same black window. **Decide first:** what a failed film should do: skip to the next row as a bad audio file does (`containingFolderIsPresent` rules: skip a bad file, stop on a vanished folder), or stop and say so. **Done when** a missing or unreadable film, in the playlist and from a browser row, is reported and the engine and window match whatever was decided. Check a missing local file, an unreadable one (non-video bytes in an `.mp4`) and an unreachable server film. Skills: `video-playback`, `audio-system`. |
