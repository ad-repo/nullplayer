| M37 | EQ rules: map an EQ setting to a track, album or artist | A rule-based system that applies a saved EQ curve automatically when a matching track starts. **Add a rule:** a button on the EQ window opens a rule editor prefilled from the current track. The editor picks the scope (this track, this album, this artist, or a whole source), and the source the rule applies to: the current track's source (local, Plex, Jellyfin, Subsonic, Emby, radio) or all sources. A track rule also picks this version (the one file or server item) or all versions (every copy of the song: other albums, remasters, live takes, other formats). It saves the current band values plus preamp as the rule's curve. **View rules:** a menu item opens a list of every rule (scope, match, source, curve name) where rules can be edited, disabled or deleted. **Matching:** the most specific rule wins (track > album > artist > source); at the same scope, a rule for one source beats an all-sources rule, and a this-version track rule beats an all-versions one. When no rule matches, the existing behaviour applies: the AUTO genre preset if it is on, otherwise the last manual setting. A manual fader drag or preset click during playback overrides the rule for that track only. Open questions: how an all-sources rule matches the same track or album across sources (by artist/album/title, since IDs differ per server), how an all-versions rule recognises the same song (artist plus title with suffixes like "Remastered" or "Live" normalised away, or MusicBrainz recording ID when tagged), and whether a rule can point at a named preset as well as a raw curve. **Done when** rules can be added from the EQ button, are listed and editable from the menu, apply on track change in Classic, Original, `.wal` and `.wmz` EQ windows, and survive a relaunch. Skills: `audio-system` (EQ, AUTO genre preset), `app-state` (persistence), `user-guide` (menus). |
